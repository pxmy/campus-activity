# 校园活动与实践管理平台 —— 10 单元开发计划

> 依据《校园活动与实践管理平台 AI 协同开发课程设计指导书》制定。
> 本计划把 10 个单元拆解为可执行的任务，明确每个单元的目标、产出文件、依赖关系与验收点，作为开工时的任务来源。

## 一、贯穿全项目的硬性约定

| 类别 | 约定 |
|---|---|
| 分层 | 界面层 `pages/` 只做输入输出；业务规则和统计口径只写在 `services/`；`services/` 不得导入 streamlit；界面层不得出现 SQL |
| 模型调用 | 全项目只有 `services/llm.py` 读取密钥、创建客户端；其它模块一律通过它提供的函数调用模型 |
| 密钥 | 密钥只出现在 `.env`（git 忽略）和本机 Continue 配置；仓库中只保留 `.env.example`；历史提交不得出现 `sk-` |
| SQL | 一律使用参数占位符，禁止字符串拼接 / f-string 拼入变量 |
| 时间 | 统一 ISO 8601 字符串，如 `2026-12-05T14:00`；字符串比较与时间比较结果一致 |
| 路径 | 一律用 `pathlib`，相对项目根目录，不写绝对路径 |
| 取整 | 用 `Decimal` + `ROUND_HALF_UP`，禁止内置 `round()` |
| 缺失值 | 保持为空，不得用 0 / 平均值 / 猜测值填充 |
| 数据 | 活动和报名不做物理删除，只改状态；被取消的报名不占名额、被取消的活动不占场地 |
| 测试 | 改 `services/` 代码须同步更新测试；测试不访问网络，模型相关用替身函数 |
| Git | 每单元验收后在主分支打标签 `u1`…`u9`，发布打 `v1.0`；提交说明以单元编号开头 |

## 二、单元任务分解

### 单元 1：需求定义与项目启动
- **目标**：把模糊想法落实为可验收需求、数据结构和可运行骨架。
- **产出文件**：`docs/需求文档.md`（业务流程图 Mermaid + 状态转换规则 + ≥12 条用户故事）、`docs/数据字典.md`、`.gitignore`、`.env.example`、`requirements.txt`、`db/schema.sql`、`db/init_db.py`、`services/db.py`、`services/auth.py`、`app.py`、`pages/` 占位页、`README.md`、`.continue/rules/01-project.md`。
- **依赖**：无（起点）。
- **验收点**：按 README 能建库启动；侧边栏可切换用户；占位页按角色显示/拒绝；`.env` 未入库；项目指令生效；打标签 `u1`。

### 单元 2：活动管理、报名与教学事务
- **目标**：实现核心业务，保证四类规则正确（人数、重复报名、场地冲突、成绩计算）。
- **产出文件**：`services/rules.py`、`tests/test_rules.py`（≥25 条，成绩 ≥12 条）、`pages/1_活动管理.py`、`pages/2_报名与成绩.py`、`docs/业务规则.md`。
- **依赖**：单元 1 的 schema 与 auth。
- **验收点**：组织者只能操作自己的活动；三类报名拒绝有明确提示；场地冲突重叠拒绝、首尾相接通过、排除自身；pytest 全过；成绩显示“未评定”而非 0；学生只看本人成绩。打标签 `u2`。
- **重点陷阱**：检查与写入同一事务；`round(82.5)=82` 银行家舍入，必须用 `Decimal`。

### 单元 3：数据清洗与办公文档生成
- **目标**：历史报名/成绩文件入库，干净数据进库、问题数据进清单、不无声丢弃；按模板生成文档。
- **产出文件**：`services/cleaning.py`、`services/docgen.py`、`tests/test_cleaning.py`（覆盖 8 类问题）、`pages/3_数据导入.py`、`templates/` 两个模板、`docs/数据清洗规则.md`。
- **依赖**：单元 1 学生名单、单元 2 活动表。
- **验收点**：读取=入库+未入库异常；异常可回溯原行；重复导入不产生重复；非法值不截断不猜测；生成文档无残留 `{{`。打标签 `u3`。

### 单元 4：活动统计与可视化看板
- **目标**：把数据变成指标与图表，难点在“口径”统一。
- **产出文件**：`services/stats.py`、`tests/test_stats.py`、`pages/4_统计看板.py`、`docs/统计口径.md`（含表 4-7 对账表）。
- **依赖**：单元 2、3 数据。
- **验收点**：口径文档写明分子分母；指标测试含分母为 0 和取消报名；看板含卡片+对比图+分布图+明细表；筛选三处同步；CSV 带 BOM 中文正常；对账表填完。打标签 `u4`。
- **重点**：汇总比率=分子之和÷分母之和，不可对比率取平均。

### 单元 5：到场预测与活动分群
- **目标**：预测到场人数（基线 vs 回归）、按参与特征聚类，并判断模型可信范围。
- **产出文件**：`services/ml.py`、`pages/5_预测分群.py`、`docs/模型说明.md`、`data/raw/history_activities.csv`。
- **依赖**：单元 2 报名/成绩数据 + 历史活动数据。
- **验收点**：按时间先后切分 80/20；同份检验数据比较；页面给两种预测+MAE；解释 ≥2 个回归系数；聚类前标准化、固定随机种子、每簇命名；不展示个人分群；模型说明回答 4.5.4 全部问题。打标签 `u5`。

### 单元 6：反馈分析与知识问答
- **目标**：大模型成为平台功能部件；主题分类/摘要 + 带来源问答，输出须校验、回答须有据、无资料要老实说没有。
- **产出文件**：`services/llm.py`、`services/feedback.py`、`services/qa.py`、`tests/test_qa.py`、`pages/6_反馈问答.py`、`data/docs/` 资料、`docs/阈值试验.md`。
- **依赖**：单元 2 反馈数据、单元 1 llm 封装约定。
- **验收点**：断网/无密钥有友好提示；主题在体系内；注入指令不影响分类；摘要三部分带依据条数；问答列来源可展开；5 个未覆盖问题拒答；有不依赖网络的测试。打标签 `u6`。

### 单元 7：图像、语音与多模态资料处理
- **目标**：识别签到表与会议录音，重点是原始对照与人工修正（识别结果须人确认才入库）。
- **产出文件**：`services/media.py`、`pages/7_资料处理.py`、`docs/修正记录说明.md`、`data/raw/signin_*.jpg`、`data/raw/meeting.wav`。
- **依赖**：单元 2 报名表（比对）、单元 6 llm 封装。
- **验收点**：原图与识别结果并排、问题行标出；未确认不入库；修正有记录；迟到由程序判定；长录音分段且可单独重试；待办可定位原句、未明确不编造。打标签 `u7`。

### 单元 8：自动化工作流与工具调用助手
- **目标**：串联“统计—摘要—报告—归档”周报；做能调用只读工具的问答助手，设校验/权限/上限/记录。
- **产出文件**：`services/workflow.py`、`services/tools.py`、`tests/test_tools.py`、`pages/8_工作流助手.py`、`pages/9_日志.py`。
- **依赖**：单元 3 文档填充、单元 4 统计、单元 6 摘要与 llm。
- **验收点**：工作流四步可见、错误数字判定失败、无密钥降级；助手 ≥3 个只读工具；表 4-12 六项对抗测试通过；日志可按用户/工具/成功筛选；工具校验与权限有测试。打标签 `u8`。

### 单元 9：系统测试、模型评测与修复
- **目标**：不增加新功能，专门挑毛病：跨组试用、系统测试、独立数据评测、日志分析、审查修复 AI 代码。
- **产出文件**：`tests/eval_*.py`（不进 pytest 自动范围）、`docs/测试与缺陷记录.md`、`docs/模型评测记录.md`、`docs/已知问题.md`。
- **依赖**：前 8 单元全部功能。
- **验收点**：≥5 条缺陷单；≥30 条测试三类齐全；5 项智能功能独立数据评测；日志分析发现 ≥1 问题；每人 1 条缺陷修复+回归测试；已知问题清单。打标签 `u9`。

### 单元 10：发布交付与个人答辩
- **目标**：证明干净环境可运行，证明每人真正理解自己的部分。
- **产出文件**：`docs/发布说明.md`、`docs/课程设计报告.md`、每人 AI 协作日志（见 `docs/AI协作日志模板.md`）、表 4-16 演练记录。
- **依赖**：全部。
- **验收点**：他人只按 README 可启动；配置依赖 7 项通过；5 项异常演练；完成版本回退；贯穿演示；个人解释与现场变更。打标签 `v1.0`。

## 四、实施顺序说明

1. 先完成 U1 骨架（schema + db/auth + app + 占位页 + 配置），确保能启动。
2. U2 是核心：先写 `tests/test_rules.py` 再实现 `rules.py`，务必覆盖 `round()` 陷阱。
3. U3/U4 是数据与口径：清洗“不无声丢弃”，统计“分子之和÷分母之和”。
4. U5/U6/U7 是智能功能：U6 的 `llm.py` 要先做好，U7 复用它。
5. U8 把前面能力串起来；U9/U10 偏向测试、评测、文档与演练。

> 说明：智能功能（U6/U7/U8 的模型调用部分）依赖真实 DeepSeek 接口与本机的模拟数据文件。本项目已按指导书附录实现全部代码结构与纯逻辑测试；涉及真实模型的函数需在配置好 `.env` 密钥后于本机联调，评测脚本按指导书要求不纳入 pytest 自动运行。
