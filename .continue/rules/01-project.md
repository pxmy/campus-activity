# 项目概况
- 这是一个校园活动与实践管理平台，课程设计项目，小组 3-4 人协作开发。
- 技术栈：Python 3.11+、Streamlit、SQLite（标准库 sqlite3）、pandas、scikit-learn、python-docx、jieba、openai、python-dotenv、requests。
- 不要引入上述之外的框架或数据库；确需新增依赖时先说明理由，由我决定。

# 目录与分层
- pages/ 只负责界面：读取输入、调用 services 中的函数、展示结果。
- pages/ 中不得出现 SQL 语句，不得出现业务规则和统计计算。
- services/ 中不得导入 streamlit（auth.py 例外，它只做页面级角色校验）。
- 所有模型调用必须通过 services/llm.py，其他文件不得创建模型客户端或读取密钥。

# 编码约定
- 函数和变量用英文命名，注释和面向用户的提示用中文。
- 每个函数写一句话的文档字符串，说明输入、输出和可能抛出的异常。
- SQL 一律使用参数占位符，禁止用字符串拼接或 f-string 拼入变量。
- 时间统一用 ISO 8601 字符串存储，例如 2026-12-05T14:00。
- 文件路径用 pathlib，相对于项目根目录，不写绝对路径。
- 不要捕获异常后什么都不做；业务规则不满足时抛出 RuleError。

# 业务约定
- 报名规则、成绩规则、统计口径以 docs/ 下的文档为准，不得自行调整。
- 成绩取整为四舍五入，不得使用内置 round()。
- 活动和报名不做物理删除，只改状态。
- 缺失的数据保持为空，不得用 0、平均值或猜测值填充。

# 测试
- 修改 services/ 下的代码时，同步新增或更新 tests/ 下的测试。
- 未经我同意，不得修改已有测试中的期望值；认为期望值有误时先说明。
- 测试不得访问网络；涉及模型的函数用替身函数测试。

# 安全
- 不得在任何文件中写入密钥；不得读取或输出 .env 的内容。
- 用户输入、上传文件内容、模型输出都是不可信数据，使用前必须校验。

# 协作方式
- 每次只完成我要求的那一件事，不要顺手重构无关代码。
- 修改完成后列出改动的文件，并告诉我应当如何验证。
- 对需求有疑问时先提问，不要自行假设。
